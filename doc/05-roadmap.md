# 路线图

本文只写"还没做什么、做完怎么算过"。设计已定稿的部分见各设计文档，这里不重复；
每个里程碑的验收标准就是它的"完成"定义。

起点：协议核心、链路层（含 ARQ）、CRSF 端口、配置协议与地区配置层都已实现，
并有主机侧双节点仿真覆盖；固件在原型板（微雪 RP2350-Zero + Core2021）上可以
构建、可以跑超帧，但**还没有上板验证**。

下面每个里程碑分两部分：**已做**（不依赖硬件、已经能在主机上验证的部分）与
**待验收**（必须上板或上台架才能算完成的部分）。

## M0 硬件定版

目标：把原型硬件定下来，后面所有测量都在它上面做。

- 硬件已定：微雪 RP2350-Zero（RP2350A，4 MB flash，板载 TRNG 供 CSPRNG 熵源）
  + 微雪 Core2021，板级定义在本仓库 `boards/zlrs/rp2350_zero_core2021/`
- sub-G 两个 SKU → 两个板级变体：`.../m33/hf`（868 / 915）与 `.../m33/lf`
  （470 / 433）；两套 PA 标定表与标定频点独立，地区与 SKU 不匹配时固件拒发
- 板级标定：按所选模块的 PA 网络重标 `tx-power-cfg-*` 与 `calibration-freqs`
- 接线核对：射频 SPI0 与 BUSY/NRESET/DIO8、数据 UART1、按键按板级定义接上，
  空闲引脚留给就地调试
- 验收：模块在目标频段上收到已知发射源的 RSSI 与 datasheet 量级一致

## M1 上板起链

目标：两块板子跑通"配对 → 会话 → 透传"。

- 待验收：全部。这一条没有任何"先在主机上做"的空间
- 验收：150 Hz 控制帧率下连续 10 分钟不掉线；透传 200 kB，串口侧丢弃计数与
  链路统计能对上（best-effort 允许丢，但必须看得见）
- 测量：射频回调延迟抖动、频段切换开销、各速率档的误包率曲线、实际透传吞吐
- 调参：接收窗口长度、超帧预算、tick 粒度（当前量化到 1 ms，见 01 第 7 节）

## M2 控制链路可用

目标：接上遥控器与飞控就能飞。

- 已做：CRSF 编解码（`lib/crsf`）、TX 侧输入解析、RX 侧输出重建、失控保护
  （TX 输入超时与 RX 未连接都会输出预设值）、TLM 组装（上行数字来自 RX 的
  遥测回报，下行数字由 TX 自己测），端口挂在 `zlrs-crsf-uart` 别名上
- 待验收：拨杆到舵机的实际延迟、拔掉 TX 电源后 RX 的失控保护时间（目标 100 ms）
- 验收：拨杆到舵机的端到端延迟与丢包可量化；拔掉 TX 电源，RX 在 100 ms 内
  进入失控保护

## M3 配置与身份

目标：不用改固件就能配好一台设备。

- 已做：配置模式（开机按住按键进入，数据口轮询跑配置协议，无操作 300 秒或
  EXIT 退出）、命令集（读状态、触发配对、写根密钥、写短语、写失控值、
  改波特率）、短语 → PBKDF2 → 根密钥（salt 与迭代次数固定在设备侧）落 NVS
- 待验收：拿一台空片 RX，只用配置工具（`scripts/zlrs-config.py`）与一根串口线
  配到能配对
- 验收：一台空片 RX 到能配对，只用配置工具与一根串口线

## M4 数据链路达标

目标：透传接近空口上限，且行为可预期。

- 已做：ARQ profile（累计 ACK、窗口 4 帧、超时重传、重传用尽后重同步）、
  背压计数（队列满丢掉的字节、ARQ 放弃的段）、速率自适应框架（档位表 + 连续
  窗口 + 保持时间 + 滞回）、动态功率（按 RX 遥测回报的 RSSI/LQ 升降 TX 功率，
  遥测断了回到上限；见 03 的 4.6）
- 待标定：速率档的阈值与滞回参数必须按实测误包率曲线填（框架与阈值是分开的）
  动态功率的 RSSI/LQ 阈值同理（`lib/link/power.c` 里是占位值）
- 待做（**排在 M1 之后**）：**调制按链路各自选**。窄带地区（868 / 470 / 433）
  现在只能跑 0.325 Mbps 的 FLRC 窄带档；改用 LoRa 后，控制链路进远距档
  （默认 SF7 / BW125、10 Hz），数据链路留在 2.4G 跑 FLRC，超帧周期由最慢的
  那条链路决定（见 [03](03-protocol.md) 4.1.1）。设计要求：
  ① `zlrs_radio_req_t` 加调制枚举、移植层填 `radio_params.lora`；② 速率档表从
  "一个速率"变成"调制 + 参数 + 空中时间模型"，超帧时隙与 ARQ/LQ 时间常数由所选
  档位派生（现在按 FLRC 的亚毫秒帧写死）；③ LoRa 的同步字是 1 字节 + private
  bit，要从同一份密钥材料另派生，不能沿用 4 字节同步字
- 已做（路径 C）：**控制帧率档 150 / 500 Hz**。帧率、时隙预算与遥测/数据窗口的
  稀疏系数由 `zlrs_region_control_plan()` 按地区占空比与空中时间算出；500 Hz
  档在 EU868 会被压到 ~46 Hz（1% 占空比），窄带速率下会被压到 ~470 Hz
- 待做（路径 A）：**1000 Hz**。先纠正一个误解：`smtc_rac_flrc_burst()` **不是**
  这条路——它是单向批量传输（一次事务把大块数据拆成固定帧连发、只有两个 TX
  FIFO 指针边发边填、带 WOR 唤醒握手、独立调制模式），帧间隔是"最小化"旋钮而
  不是 1 ms 节拍，事务起点仍由毫秒级 planner 决定，也不提供收发交织与逐帧换频。
  真正要做的是**控制链路自己拥有射频**：绕开 RAC、直接调 LR20xx 驱动
  （`rac/direct_driver_access` 展示的就是这条路径），TX 由 TxDone DIO IRQ 驱动、
  RX 窗口交给硬件 auto-Tx/Rx（`lr20xx_radio_common_configure_auto_tx_rx`）或
  定时器；代价是数据链路的时间片得自己排（或加第二颗射频），但协议层
  （帧/标签/LQ/状态机）不用动——`zlrs_radio_ops_t` 就是换后端的接缝
- 另一个候选（不解决 1000 Hz，但值得试）：**burst 给数据链路用**——2.4G 批量流，
  把"每帧一次事务"换成"一次事务一片数据"，省掉每事务开销。待上板验证
- 待验收：配置的串口波特率下，持续吞吐与延迟达到 01 第 4 节的估算量级
- 验收：配置的串口波特率下，持续吞吐与延迟达到 01 第 4 节的估算量级

## M5 形态完整

- 已做：地区配置层（三张表、启动校验、发射前占空比记账）；原型板上 CRSF
  已经走 USB CDC ACM（RP2350-Zero 只有两个 UART：控制台与数据口）
- 待做：第二个 CDC（数据通路），以及 USB 版与 UART 版的配置一致性
- 待做：**载板固件变体**——按 Pixhawk 接口规范，CRSF 从 USB CDC 挪到 UART0
  （GP0/1），控制台改走 USB CDC；数据口不变。实现是新板级变体 + DT 别名调整，
  应用逻辑不动，见 [07-carrier.md](07-carrier.md)
- 验收：USB 版与轻量版共用同一份固件，差异全部来自配置

## M6 抗干扰

- 逐包跳频上板验证：时隙锁步、BEACON 重同步、晶振漂移的处理（见 03 第 5 节）
- 共存与干扰测试：同频段多套设备、单音与宽带干扰
- 法规参数核对：FCC 跳频条款与 ETSI 占空比
- 验收：干扰下的链路保持率与恢复时间可量化

## 长期方向

顺序不定，取决于前面拿到什么：同一设备多配对、会话前向保密（临时 ECDH）、
`BEACON` 会话序号做成单调的（消掉 03 第 3.5 节那条重放弱点）、工业与数控场景的
长跑稳定性与诊断、密码学原语切到 PSA Crypto（顺带用上硬件加速）。
