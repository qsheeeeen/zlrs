# 安全模型

本文回答"谁能连、怎么建立、密钥从哪来、挡得住什么"。空中帧格式见 [09-protocol](09-protocol.md)，固件行为见 [08-firmware](08-firmware.md)。

设计约束：不做产线、不用全局公共密钥、用户自己配密钥、多台设备可以共享根密钥但同一时刻只有已配对的两台能通。

## 1. 结论摘要

- 身份分两级：**信任域**（根密钥，多台共享）与**配对**（决定当前是哪两台在通）。
- 根密钥不是链路凭据，而是**配对的授权凭据**。
- 同一时刻只保留一个配对，换绑靠重新配对。
- **配置走有线**（配置 CDC，每台设备一次，写入根密钥），**配对走空中**（长按按键）。
- 配对是三次握手：只交换设备标识与两个随机数并互相认证，空中不传任何密钥。
- 设备身份由首次启动时的 RNG 自行生成，不需要产线。

## 2. 数据

| 名称 | 长度 | 来源 | 可见性 |
| --- | --- | --- | --- |
| `root_key` | 32 B | 用户配置（配置工具写入） | 保密 |
| `salt` | 16 B | 固定常量，含 KDF 版本号（`zlrs/kdf/v1`） | 公开 |
| `dev_id` | 4 B | 首次启动 RNG 生成 | 可公开 |
| `pair_salt` | 8 B | 配对时双方各出一个 nonce | 可公开 |
| `pair_key` | 32 B | 配对时派生，不存储（用 `dev_id` 与 `pair_salt` 重算） | 保密 |

`dev_id` 与 `pair_salt` 存 NVS，配对时明文交换，都不算秘密；冒充 `dev_id` 需要先过 MAC 认证。未配置 `root_key` 的设备不参与配对，也不接受数据。

## 3. 派生结构

```
root_key (32B, 用户配置, 组内共享)
  auth_key = KDF(root_key, "zlrs/auth")                  -> 配对握手认证
  pair_key = KDF(root_key, "zlrs/pair", sort(dev_id_a, dev_id_b) || sort(nonce_a, nonce_b))
    fhss_seed = KDF(pair_key, "zlrs/fhss")[:4]           -> 跳频表种子
    sync_ctrl = KDF(pair_key, "zlrs/sync/control")[:4]   -> sub-GHz 同步字
    sync_data = KDF(pair_key, "zlrs/sync/data")[:4]      -> 2.4G 同步字
    link_auth_ab = KDF(pair_key, "zlrs/link-auth", dev_id_a || dev_id_b)  -> 每包 tag
    link_auth_ba = KDF(pair_key, "zlrs/link-auth", dev_id_b || dev_id_a)  -> 反向那把
    session_ab   = KDF(pair_key, "zlrs/session", nonce_t || nonce_r || dev_id_a || dev_id_b)
    session_ba   = KDF(pair_key, "zlrs/session", nonce_t || nonce_r || dev_id_b || dev_id_a)
                                                          -> 每次会话重算的一对
    link_enc  = KDF(pair_key, "zlrs/link-enc")            -> P2 加密钥匙（最后做）
```

链路层只接触派生值，不直接接触 `root_key`。`pair_key` 的上下文是**排序后**的双方 `dev_id` 加**排序后**的两个配对 nonce：排序让两端各算一次就一致；nonce 让"这一对设备"与"这一次配对"分开，每次配对换一份 `pair_salt`，旧配对的录制作废。代价是 `pair_salt` 要落盘。

`link_auth` 与 `session` 各是一对钥匙，方向由双方 `dev_id` 的先后顺序表达：本机发出的帧用 out，校验对端帧用 in。两个方向共用一把的话，把自己发出的帧打回自己会被当成对端帧收下（反射）。

上空中出现的三个值（`fhss_seed` 与两个同步字）都是 `pair_key` 的单向派生值，听到也推不出密钥。

## 4. 配对流程

前提：两端都已配置同一个 `root_key`，且两端都物理进入配对模式（长按按键），配对期间使用最低发射功率。

1. TX 长按按键进入配对模式并降到最低功率；RX 同样长按进入。
2. TX 发 `PAIR_REQ`，携带 `dev_id_a`、`nonce_a` 与 `MAC_a`。
3. RX 校验 `MAC_a`，记下 `dev_id_a`，生成 `nonce_b`，回 `PAIR_RESP`（带 `dev_id_b`、`nonce_b` 与 `MAC_b`）。
4. TX 校验 `MAC_b`，记下 `dev_id_b`；双方各自派生 `pair_key` 及其派生值。
5. TX 发 `PAIR_CFM`（携带 `MAC_c`）；RX 校验后记下配对、退出配对模式。
6. TX 记下配对、退出配对模式，恢复功率，进入常态。

```
MAC_a = MAC(auth_key, "zlrs/pair/req"  || dev_id_a || nonce_a)
MAC_b = MAC(auth_key, "zlrs/pair/resp" || dev_id_b || nonce_a || nonce_b)
MAC_c = MAC(auth_key, "zlrs/pair/cfm"  || dev_id_b || nonce_b)
```

MAC 里同时包含两个 nonce，无法重放旧握手；三条消息带各自的标签，收发角色由状态机把着。配对**不传输任何密钥**：只认证 `dev_id` 并交换两个 nonce。

规则：

- 配对模式必须**长按按键**进入，超时（30 s）自动退出。
- 常态下设备拒绝一切配对握手，无法被远程抢占。
- 配对成功即**替换**原有配对（同一时刻只保留一个）；换绑就是一次新的配对。
- 多台 RX 同时处于配对模式时先响应者胜出——配对时只给目标 RX 上电，或用贴身低功率压低覆盖范围。

## 5. 会话建立（与配对区分）

配对决定"和谁通"，会话决定"这一次用什么钥匙"：`pair_key` 在配对时两端各自算好，会话只给它换一对每次都不同的 nonce，不改持久状态、不需要用户参与。流程见 [09-protocol](09-protocol.md) 3.5，安全性质：

- **双方各出一个 nonce**：TX 出 `nonce_t`，RX 出 `nonce_r`，两个都进会话钥匙。只靠 TX 那个可被整帧重放的值不够——录一个旧 `SYNC` 重放，RX 就会重算出那次会话的钥匙。
- **采用会话要等确认**：TX 用新钥匙打一条 `SESS_CFM`，RX 验过才采用；重放的旧帧用的是当时的 `nonce_r`，对不上。
- **只换流密钥，不换身份**：会话重算不动配对记录；`nonce_t`、`nonce_r`、会话密钥与序号都不落盘，掉电即失效。
- **`SYNC` 用配对级的 `link_auth` 认证**：nonce 虽然公开，别人造不出能过校验的会话消息。

## 6. 对空中格式的影响

- 帧里不带任何身份字段：过滤交给射频同步字，不匹配的包在射频层就被丢弃。
- 跳频表由 `fhss_seed` 生成，两端各自算。
- 每包带序列号（防重放）与 4 B tag（P0 不带 tag，见 [09-protocol](09-protocol.md) 2.3）；方向不在帧里，在 tag 钥匙里。
- 配对握手用独立的包类型，只在配对模式下接收。

## 7. 安全性质与已知弱点

### 7.1 对手模型

| 级别 | 对手 | 能力 |
| --- | --- | --- |
| L1 | 同场飞友 | 误占频段；基本不可能知道你的短语 |
| L2 | 有 SDR 的爱好者 | 录包、重放、伪造、逆向固件 |
| L3 | 有组织的攻击者 | 长期监听、侧信道、社工 |

**本设计针对 L1 与 L2，明确不防 L3**：不做前向保密（要做得在会话建立时加临时 ECDH），并接受"知道 `root_key` 的人能在配对窗口抢走配对"。对 L1/L2 而言，伪造一个包需要先破 HMAC-SHA256，现实中不可行。

### 7.2 分层

| 威胁 | 谁 | 靠什么挡 |
| --- | --- | --- |
| 组内其它设备误占链路 | 有 `root_key` 的自己人 | 配对记录 + 逐对密钥 |
| 外部攻击者伪造/占用 | 没有 `root_key` | 每包 tag、会话 nonce |

第一类**用密码学挡不住**：组内设备本来就持有 `root_key`，`pair_salt` 又是明文交换的。拦住日常互扰的是"只认配对时记下的 `dev_id`"这条本地规则——配对限制的是**合法设备之间**的互扰，不是对抗攻击者。

能防：不同用户之间的碰撞与误占、未配对设备占用链路（即使它知道 `root_key`）、报文伪造与重放、反射、换绑后旧录制作废、配对过程中的中间人。

防不住：

- **`root_key` 泄露**：拿到根密钥的人可以主动与任何同组设备配对，顶掉原来的配对。缓解是配对要物理接触加按键。
- **没有前向保密**：根密钥泄露后，过去录下的加密流量可被解开。
- **组内成员可以互相冒充，换绑也不吊销听过新配对的旧对端**：要真正吊销只能换 `root_key`。
- **撤销只能逐台做**。
- **P0 档没有任何认证**：极致性能档不带 tag，可被注入；只在可信环境（竞速场地）使用。

## 8. 参数与算法

- 用户输入形式：**短语**，最小 12 字符，低于 16 字符给强度提示；配置工具支持一键生成。
- MAC：HMAC-SHA256 截断到 4 B，让 PBKDF2 / HKDF / MAC 全落在 SHA-256 一族，P1 不必引入 AES。
- KDF 放在**设备侧**：任何配置器送同一个短语进来都得到同一个密钥，参数（迭代次数、salt、标签）由固件定义，第三方工具改不了。
- 迭代次数 100,000（目标 MCU 上约 1–2 秒），随 KDF 版本号发布，发布后不能原地修改。
- salt 固定（含版本号）：同一个短语要在两台设备上导出同一个密钥，盐就不能每台随机；防护放在迭代次数与短语长度上。

算法选型：

| 用途 | 算法 |
| --- | --- |
| 短语 → 根密钥 | PBKDF2-HMAC-SHA256 |
| 根密钥 → 派生值 | HKDF-SHA256 |
| 每包 tag | HMAC-SHA256 截断 4 B |
| P2 加密（最后做） | AES-CTR，MAC 覆盖密文（encrypt-then-MAC） |

设备侧原语走 Zephyr 的 PSA Crypto（`lib/proto/crypto_psa.c`）；主机侧测试用一份同接口的纯 C 实现（`tests/host/crypto_soft.c`），两边用固定向量对拍。

## 9. 分层边界

协议核心不接触短语，也不接触 `root_key`，只接收派生好的 `fhss_seed`、两个同步字、按方向分开的 `link_auth` / `link_enc`，以及派生它们的输入（双方 `dev_id` 与 `pair_salt`）；会话密钥在链路层内按 `nonce_t` 与 `nonce_r` 现算。

## 10. 配置通道

配置走**专用的配置 CDC**（见 [08-firmware](08-firmware.md) 第 1 节）：插上 USB 就能配置，**不做额外认证**——能物理接触 USB 就是授权。

配置工具先在配置 CDC 上发"进配置模式"命令；设备进入配置模式后射频完全停，数据口收到的字节丢弃并计数，退出后恢复（见 [08-firmware](08-firmware.md) 第 2 节）。

### 配置协议

```
[0xA5][0x5A][ver=1][cmd][len][payload][crc8]      crc 覆盖 ver..payload
```

命令集（覆盖全部用户参数，见 [08-firmware](08-firmware.md) 第 3 节）：

| 命令 | 说明 |
| --- | --- |
| 读状态 | 角色、链路状态、标志、`dev_id`、`peer_id`、LQ、本机 sub-G 硬件 |
| 进配置模式 | 正式入口（替代早期的魔数手段） |
| 触发配对 / 擦除配对 | |
| 写短语 | 设备侧 PBKDF2 派生根密钥 |
| 写根密钥 | 64 位 hex |
| 写失控值 | 22 字节 CRSF 通道载荷 |
| 设数据口波特率 | 下次启动生效 |
| 设地区 | 写入时校验本机 SKU，不匹配拒绝 |
| 设功率上限 | 不超过所选地区的法规上限 |
| 恢复出厂 | 清 NVS |
| 退出 | 结束配置模式 |

设备对每条命令回 `ACK`（原命令 + 状态码）或 `STATUS`；参数不合法、落盘失败、命令不认识都如实回状态码。两条与安全相关的规则：**短语的派生规则固定在设备侧**；**配置模式只能从配置 CDC 进入**（调试构建额外允许 console 与数据口魔数，见 [12-debug](12-debug.md)）。

仓库自带最小命令行工具 `scripts/zlrs-config.py`（`--self-test` 校验组帧与固件一致）；任何第三方工具按同样的帧格式说话都能用。
