# 纯数传架构

本文规定模块职责、数据归属、线程边界和接口约束。需求见[产品定义](01-product.md)，空中格式见[空中协议](08-protocol.md)，操作见[固件行为](07-firmware.md)。

## 需求与模块边界

设备提供一条双向透明字节流，入口为 USB CDC 或 UART。业务包括配对、认证、会话、防重放、ARQ、质量反馈、调功、区域限制、管理、升级回滚、日志、按键和 LED。

一个 LR2021 半双工实例承载一个活动 FLRC DATA 频段，启动配置选择 2.4 GHz 或板载 sub-G。自动换频与双频调度属于未来扩展，须有双方协调协议。

| 模块 | 拥有的数据和职责 | 接口边界 |
| --- | --- | --- |
| 应用生命周期 | 初始化结果、主循环、维护窗口、配对落盘、故障恢复 | 编排业务，不建立另一份全局设备状态 |
| 持久化 | 参数、设备身份、根密钥、配对记录、存储布局 | 提供读取、校验、保存，不调用 RF、串口或 UI |
| 串口 | DATA USB/UART、队列、端口选择、背压、溢出计数 | 提供读字节和接受整包，不认识配对、ARQ、密钥或调功 |
| 管理 | 管理端点、消息解析、期限、命令与应答 | 在授予的维护窗口内执行操作，不嵌套暂停 RF |
| RF | 单个链路实例、频段、频道计划、时隙、相位、占空比、功率 | 接入协议、串口、无线电和时钟，发布状态并返回配对结果 |
| UI | 按键去抖、长按、LED 优先级、颜色和节奏 | 读取状态、发布输入，不执行协议、管理或存储操作 |
| 升级生命周期 | 镜像确认、回滚期限、恢复模式 | flash 操作完成后才报告成功 |
| 日志 | 日志存储、文件信息和字节读取 | 使用业务错误结果，不依赖管理协议结构 |
| 诊断 | 公开观察值的格式化 | 不遍历其他线程的可变对象 |
| 协议核心 | 配对、会话、帧序号、同步跳频、ARQ、接收质量 | 纯 C、显式实例、同步操作，不访问硬件或 flash |
| 硬件适配 | LR2021、FIFO、IRQ、时钟、SHA、温度、看门狗 | 返回硬件结果，不持有协议状态机 |

配对、会话和 DATA 共用一个链路对象。业务模块按职责组织，不增加通用 provider、设备注册框架、业务 callback 表或状态汇总层。硬件差异由硬件描述和已有驱动接口表达。

## 线程与数据路径

主线程拥有协议和业务状态修改。USB/UART 中断及工作队列只搬运字节；定时器中断只执行精确定时动作，不执行协议、持久化或 UI。

正常循环须处理管理输入、按键请求、RF 帧、配对落盘、状态发布及回滚期限。初始化失败仍须保留管理和恢复入口。

~~~mermaid
flowchart LR
    Host[主机 DATA] <--> Serial[串口队列]
    Serial <--> RF[RF 时隙与运行策略]
    RF --> Link[协议状态机]
    RF --> Radio[无线电硬件]
    RF --> Power[功率策略]
    Main[应用主线程] --> RF
    Main --> Mgmt[管理会话]
    Main --> Persist[持久化]
    Mgmt --> Persist
    Mgmt --> RF
    Main --> Boot[升级生命周期]
    RF --> Bus[zbus 状态]
    Serial --> Bus
    Mgmt --> Bus
    Bus --> UI[按键与 LED]
    UI --> Input[zbus 输入]
    Input --> Main
~~~

管理、配对落盘、镜像确认和日志同步须在帧边界进入维护窗口：取消发射，结束硬件事务，丢弃预编码包；维护后按实际经过时间恢复帧与跳频进度。

时隙采用绝对边界，每帧 A/B 两个时隙。短包不得提前下一时隙，准备失败不得晚发。关键时序路径须在 SRAM 中运行。

链路发送队列负责等待空中 ACK；串口队列负责主机端消费。收到 DATA 只有在串口接受整包后才推进 ACK。USB 堵塞保持背压，UART 溢出须计数，不合并两种队列的职责。

## 持久化契约

| 持久化内容 | 运行内容，不得持久化 |
| --- | --- |
| 频段、角色、区域、profile、UART 波特率、功率上限 | 活动射频参数、实际功率、占空比预算 |
| 设备 ID、根密钥、peer ID、配对 salt | 会话密钥、帧序号、ARQ、反馈与队列 |

读取接口按设置、身份、根密钥、配对记录分组。缺项须明确报告，且不修改调用方输出。读取使用已加载的快照，保存成功后才更新快照。

普通参数重启生效。凭据更换、删除配对和恢复出厂须在同一维护窗口使相应链路失效。持久化模块不得隐式重启或调用 RF。

配对结果与保存记录不同才写入。保存失败保留原记录，并允许后续重试；删除配对须同时清除活动结果，防止旧配对再次落盘。真实 flash 错误与记录缺失分别处理。

扇区大小取硬件擦除粒度，扇区数取分区容量；应用不得重复定义硬件约束。

## 状态通信与 UI

跨线程状态及按键输入采用 zbus。业务模块维护事实，通道副本仅供观察，不成为另一份可修改状态。

| 通道 | 发布者 | 内容 |
| --- | --- | --- |
| RF 状态 | RF，在主线程安排的边界发布 | 角色、频段、区域、链路、质量、功率、故障、链路丢字节 |
| 串口状态 | 串口，在主线程安排的边界发布 | 可用性、活跃端口、背压、串口丢字节 |
| 管理状态 | 管理 | 会话是否进行中 |
| 按键输入 | UI | 累计长按次数 |

通道不承载 DATA、密钥、链路对象指针或逐条管理命令。通知用于唤醒，消费者读取最新值并周期补读，不要求逐条回放或全局原子快照。

发布失败须在后续边界重试，不能阻塞 RF。长按以累计次数保留，通知合并不得抹掉请求。主线程在自身上下文消费输入。

一个低优先级 UI 线程拥有按键和 LED。按键每 20 ms 采样，显示以 20 Hz 刷新，仅在输出颜色变化时写入设备。读取快照后须释放通道锁，再执行 GPIO/LED 操作。颜色、优先级和持续时间只属于 UI。

## 协议、硬件与策略接口

协议接口接收帧、时间及硬件结果，并返回下一事务。纯核心不得依赖 Zephyr、zbus、日志或板型。管理帧层只定义 SOF、版本、长度和 CRC，业务命令由管理模块执行。

无线电适配须返回状态、长度、RSSI 和完成时刻，RF 再推进协议。功率策略输入对端质量、反馈时刻、当前时刻及上下限，输出设定值；RF 执行区域限制并应用结果。

数据交付接口须报告是否接受整包，以决定 ACK。随机源接口须报告成功或失败；安全随机失败不得退回时间或计数器。

角色、区域、profile 和链路状态采用领域类型。空中帧和持久化记录按明确字节规则编码，不直接传输内存布局。

外部输入须检查长度、版本、CRC、认证、重放、FIFO 容量和时限。预编码包须仍属于当前会话、DATA 序号及发送序号。预装包保留 ACK 快照，后到的新 DATA 留下待确认状态，不能把尚未发送的 ACK 当作完成。

## 验收条件

须验证双节点配对、握手、防重放、双向 DATA、重传、背压和质量窗口，覆盖两个角色及两个频段的时序、故障、维护恢复和调功。

存储验收覆盖加载、缺项、保存失败、重启、凭据变更和删除配对。UI 验收覆盖优先级、节奏、长按及通知遗漏。升级验收覆盖确认失败、恢复入口、回滚期限及初始化失败后的管理可达性。

构建须覆盖 LF/HF 及调试配置，并检查层次边界和关键 SRAM 路径。验证结果独立于设计文档保存。
