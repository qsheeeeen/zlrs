# User experience: the button and the status LED

The device has no screen, so all the user can touch is **one button** and **one RGB LED** (the WS2812 on the RP2350-Zero). This document fixes what those two mean. Ports and modes: [08-firmware](08-firmware.md); protocol: [09-protocol](09-protocol.md).

The goal: **you can tell what state the device is in without a computer**, and never by colour alone: colour and cadence both carry information.

## Button

The button has exactly one action:

| Action | Condition | Result |
| --- | --- | --- |
| Long press | hold for 1 s or more (`CONFIG_ZLRS_APP_PAIR_HOLD_MS`) | start pairing (the handshake) |

There is no short press: releasing before 1 s does nothing. Pairing has consequences, so it is worth holding a moment longer and cannot happen by accident. Re-binding is a long press too: the new pairing record replaces the old one; there is no separate unpair action.

The button is standard equipment: the carrier board has one (SW1, GP12 to ground with an internal pull-up); on the prototype a jumper wire from GP12 to GND stands in for it.

**Configuration does not use the button**: config mode is entered by a command the tool sends on the config CDC (see [10-security](10-security.md) 10), with no physical action at all.

One press triggers pairing once; a new press needs a release in between. TX and RX share the same button semantics.

## Status LED

One pixel cannot say much, so the LED uses both **colour and cadence** with fixed priorities: at any moment it shows the single most important thing (the only exception is the data-drop hint, which overlays the connected state).

| Priority | State | Colour | Cadence | Notes |
| --- | --- | --- | --- | --- |
| 1 | Config mode | white (shared alert colour) | 1 Hz, 500 ms on | outranks everything; only after 0.5 s of session, so tool round-trips do not flash |
| 2 | Failsafe | red (shared alert colour) | 1 Hz, 800 ms on | only after a first connection: the TX hears no stick data, or the RX lost the link |
| 3 | No root key | purple (shared alert colour) | 0.5 Hz, 200 ms on | time to run the config tool |
| 4 | Configured, not paired | yellow (shared alert colour) | 1 Hz, 120 ms on | waiting to be paired |
| 5 | Pairing | **theme colour** (blue for TX, green for RX) | 1 Hz, 300 ms on | |
| 6 | Searching | theme colour | 0.5 Hz, 150 ms on | paired, no session yet |
| 7 | Connected | theme colour | steady | LQ 80 or more is 30% brightness, 50-79 is 18%, below 50 is 10% |
| - | Boot self-test | theme colour | steady for 1.5 s | tells TX from RX at a glance |
| - | Data drops (overlay) | orange (shared alert colour) | one 300 ms flash every 2 s | only overlays while connected |

Trade-offs:

- **30% brightness ceiling**: this is an indicator, not a lamp: it does not glare at night and costs nothing in the power budget.
- **No fast blinking for steady states**: connected is steady; blinking is kept for things that are changing (pairing, searching) or need the user (config, unpaired, unconfigured).
- **Failsafe outranks every link state**: the first thing the user needs to know is that there is no usable link.
- **The drop hint overlays rather than replacing**: the link still runs, it is just not clean.

## Where it lives

| Part | Location |
| --- | --- |
| State to colour and cadence | `lib/led` (pure C, host-testable: `tests/host/test_led.c`) |
| WS2812 driver | `app/src/led_port.c` (PIO plus the `led_strip` API, board node `zlrs-led`) |
| Button read and debounce | `app/src/main.c` (polled in the superframe loop, no extra thread) |

Both live in the main loop: the button is a millisecond-level level check and the LED updates at 20 Hz, neither worth a thread and neither allowed to disturb radio timing.
